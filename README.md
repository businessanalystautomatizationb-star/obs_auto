# MeetingBRDAgent

Menu bar агент для macOS: управляет OBS через obs-websocket, а после остановки
записи прогоняет её через транскрибацию и Claude, чтобы получить готовый
протокол встречи.

Пайплайн: OBS стоп → ffmpeg (аудио) → Deepgram (транскрипт) → Claude API (анализ) → `.md`/`.docx` в папку.

## Как запускается и останавливается запись

**Старт — автоматически**, по точному заголовку окна звонка
(`Sources/MeetingBRDAgent/WindowWatcher.swift`):
`Zoom Meeting`, `Zoom Webinar`, `Meeting | Microsoft Teams`,
и русская локализация Zoom — `Конференция Zoom` (подтверждено на
реальном звонке). Плюс ручной старт из меню иконки → **"Начать запись"**,
если авто-детект почему-то не сработал (например, другая локаль/версия
клиента — заголовок именно этой версии Zoom можно посмотреть командой
`osascript -e 'tell application "System Events" to get name of every window of process "zoom.us"'`
во время звонка и прислать мне, добавлю точный паттерн).

**Стоп — двумя путями, что сработает раньше:**
1. Заголовок с паттерном пропал на ~12 секунд (звонок закрыт, приложение
   осталось открытым).
2. У процесса `zoom.us`/`teams` вообще не осталось ни одного окна (`.optionAll`,
   не завязано на текст заголовка) — это подстраховка, которая ловит закрытие
   даже если по какой-то причине первый способ не сработал.

Плюс "Остановить запись" в меню — прервать раньше вручную. Если после звонка
Zoom остаётся открытым на "домашнем" экране (не закрыт полностью), автостоп
по второму способу не сработает, пока приложение не закроется — тогда жми
стоп вручную.

Для чтения заголовков окон macOS требует разрешение **Screen Recording**
(System Settings → Privacy & Security → Screen Recording) для этого процесса.
Без него заголовки приходят пустыми (детект окна Zoom/Teams по владельцу
процесса работает даже без этого разрешения, а вот точные текстовые
паттерны — нет).

## Установка на новый Mac (одной командой)

В Терминале:

```bash
git clone https://github.com/businessanalystautomatizationb-star/obs_auto.git ~/meeting-brd-agent
open ~/meeting-brd-agent
```

(если macOS предложит установить инструменты разработчика — соглашайся, потом повтори команду).
Положи `config.json` со старого Mac в папку проекта, в «Загрузки» или на рабочий стол
и дважды кликни **«Установить на новом Mac.command»**. Скрипт сам поставит Homebrew,
ffmpeg, pandoc и OBS, перенесёт конфиг (поправит путь к папке протоколов под нового
пользователя), создаст сертификат подписи, соберёт приложение под этот процессор и
включит автозапуск. Руками останется: разрешение «Запись экрана» и настройки OBS
(WebSocket и источники). Лог — `install.log`. `config.json` в git не попадает
(он в `.gitignore`) — репозиторий публичный.

## Установка зависимостей

```bash
brew install ffmpeg pandoc
```

`ffmpeg` обязателен (извлечение аудио). `pandoc` опционален — конвертирует
итоговый Markdown в `.docx`; без него документ останется в `.md`.

## Настройка OBS

1. OBS → Tools → WebSocket Server Settings → Enable WebSocket server.
2. Задай пароль и пропиши его в конфиг ниже (порт по умолчанию — 4455).
3. Settings → Output → Recording: формат `mp4` (или `mov`), путь любой — агент
   сам узнаёт итоговый путь файла через obs-websocket, конфигурировать его не
   нужно.

## Конфиг и API-ключи

Первый запуск создаст `~/.meeting-brd-agent/config.json` с плейсхолдерами.
Заполни:

```json
{
  "obsHost": "127.0.0.1",
  "obsPort": 4455,
  "obsPassword": "тот же пароль, что в OBS WebSocket Server Settings",
  "deepgramKey": "ключ с https://console.deepgram.com/",
  "anthropicKey": "ключ с https://console.anthropic.com/",
  "outputFolder": "/Users/bts/Documents/MeetingDocs"
}
```

## Название протокола

Сразу после остановки записи (и при «Обработать запись заново…») поверх
окон появляется окно **«Как назвать протокол?»** с подставленной датой
встречи (`2026-11-10 `) — допиши проект и тему, Enter. Обработка в это
время уже идёт; агент ждёт ответа только перед сохранением файла (в статусе
будет «Протокол готов — жду название в открытом окне…»). Кнопка «Без
названия» или закрытие окна — протокол назовётся по имени файла записи, как
раньше. Если такое имя уже занято, добавится ` (2)` — существующий протокол
не перезаписывается. Файл расшифровки (`.transcript.txt`) по-прежнему
называется по записи — по нему работает повторная обработка
(`NamePrompt.swift`).

## Формат документа

Один универсальный протокол встречи вместо выбора между BRD/User
Story/Use Case — встречи у БА слишком разные (созвон по требованиям,
статус, интервью со стейкхолдером...), чтобы выбирать тип заранее.
Структура (`Sources/MeetingBRDAgent/PromptTemplates.swift`, за основу взят
стандартный "meeting minutes" шаблон Location/Attendees/Topic/Objectives/
Agenda/Notes/Action Items, плюс разделы под требования/риски):

- Дата и участники
- Тема и цель встречи
- Повестка
- Ключевые обсуждения и решения
- Выявленные требования
- Открытые вопросы и риски
- Дальнейшие шаги

Промпт можно отредактировать под себя в `PromptTemplates.swift` — например,
поменять формулировки разделов или добавить свой.

## Сборка и запуск

```bash
cd /Users/bts/meeting-brd-agent
swift build -c release
codesign --force --deep --sign "MeetingBRDAgent Local Signing" --identifier com.btsanalyst.meetingbrdagent .build/release/MeetingBRDAgent
.build/release/MeetingBRDAgent
```

Подпись после **каждой** пересборки обязательна — без неё macOS считает
бинарник "новым приложением" при каждом билде и молча теряет выданное
разрешение Screen Recording. Подписываем локальным сертификатом
"MeetingBRDAgent Local Signing" (создан один раз в login keychain, не
ad-hoc `-sign -`) — с ним разрешение переживает пересборки; с ad-hoc
подписью слетало почти каждый раз, потому что хэш содержимого каждый раз
новый. Если сертификата нет в системе (`security find-identity -v -p
codesigning | grep "MeetingBRDAgent Local Signing"` ничего не находит) —
скажи мне, пересоздам.

Появится иконка в строке меню: 🟡 — ожидание, 🔴 — идёт запись. Клик по
иконке → пункты меню: **"Начать запись"** / **"Остановить запись"** (ручное
управление), статус текущего шага пайплайна, открыть конфиг, открыть папку
с документами, выход.

## Автозапуск при входе в систему

Шаблон LaunchAgent лежит в `Resources/com.btsanalyst.meetingbrdagent.plist`.
Это **постоянное изменение** (агент будет стартовать при каждом входе в
систему), поэтому я не устанавливаю его без явного запроса — если хочешь,
скажи и я скопирую его в `~/Library/LaunchAgents/` и загружу через
`launchctl load`. Сделать вручную:

```bash
cp Resources/com.btsanalyst.meetingbrdagent.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.btsanalyst.meetingbrdagent.plist
```

Выгрузить/остановить автозапуск:

```bash
launchctl unload ~/Library/LaunchAgents/com.btsanalyst.meetingbrdagent.plist
```

## Известные ограничения MVP

- Русский Zoom подтверждён (`Конференция Zoom`), но точный заголовок Teams
  или Zoom на другом языке/версии не проверялся — если авто-старт не
  сработает, используй ручной старт из меню и пришли мне точный заголовок.
- Если Zoom/Teams-приложение остаётся открытым после звонка (например,
  висит на "домашнем" экране), авто-стоп не сработает, пока приложение
  не закроется полностью — тогда останавливай запись вручную из меню.
- OBS запускается лениво — не при старте агента (не висит фоном часами
  до первого звонка за день), а именно в момент, когда обнаружена
  встреча: агент открывает его тихо в фоне (`OBSLauncher.swift`,
  `open -j -a OBS`, без активации окна) и подключается по WebSocket,
  откладывая реальный старт записи до момента подключения — иконка не
  красится в 🔴 вхолостую, пока OBS ещё грузится. Сразу после остановки
  записи OBS закрывается снова (`OBSLauncher.quit()`) — дальше по
  пайплайну (ffmpeg/Deepgram/Claude) он не нужен и просто ест ресурсы.
  Если OBS неожиданно закрылся посреди записи, агент сам
  переподключается каждые 5 секунд.
- YouTube-заливка сознательно убрана из цепочки — Deepgram принимает файл
  целиком без лимита 25 МБ и качество транскрипта заметно выше. Если нужен
  архив на YouTube — это можно добавить отдельным необязательным шагом.
- Файл записи (`.mp4`/`.mov`) остаётся там, куда его пишет OBS — агент его не
  перемещает и не удаляет.
